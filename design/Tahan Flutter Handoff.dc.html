Building Tahan in Flutter

Everything in Tahan is drawn by the app: there are no photographic scene assets, no avatar images, no per-platform layout. That is deliberate — it is what lets one Flutter codebase ship an identical iOS and Android build, and it is what makes an avatar cost six bytes instead of a hosted file. This document is the contract: the theme, the two painters, the screen inventory, and the parts that must stay native.

Read alongside Tahan.dc.html — the working prototype. Where this doc and the prototype disagree, the prototype is right; it is the reference implementation for spacing, copy and interaction feel.

1 · Theme

Tahan has one base theme (Organic) and nine scene palettes that retint it. A village owns a scene; opening a village swaps the palette for the whole app, feed and chrome included. So the theme is not a constant — build it from a scene.

1.3 ThemeData from a scene

class ScenePalette { final String key, name; final Color accent, accent2, bg, surface; final bool dark; // dark sky → light ink in the header final Drift drift; // fireflies | leaves | breeze | dust | rain | snow | petals final List<GradientStop> sky; // 3–4 stops, see §2.2 const ScenePalette({...}); } ThemeData villageTheme(ScenePalette p) { final scheme = ColorScheme.light( primary: p.accent, secondary: p.accent2, surface: p.surface, background: p.bg, onPrimary: p.bg, onSurface: const Color(0xFF201E1D), ); return ThemeData( useMaterial3: true, colorScheme: scheme, scaffoldBackgroundColor: p.bg, textTheme: _figtree(scheme).copyWith( displayLarge: _caprasimo(34), headlineSmall: _caprasimo(21), titleMedium: _caprasimo(16), ), cardTheme: CardTheme( color: p.surface, elevation: 0, shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(16)), ), filledButtonTheme: FilledButtonThemeData( style: FilledButton.styleFrom( shape: const StadiumBorder(), minimumSize: const Size(0, 48)), ), extensions: [VillageScene(p)], // painters read the scene from here ); }

Put the palette in a ThemeExtension (VillageScene) so the scene painter and the avatar painter can read it from Theme.of(context) without a separate provider. Switching village = rebuilding the MaterialApp theme; give it a 420 ms themeAnimationCurve: Curves.easeOutCubic so the retint reads as the room changing, not a flash.

2 · The scene painter

One CustomPainter draws all nine scenes. A scene is an ordered list of flat primitives over a vertical sky gradient — no images, no blurs, no shaders.

2.1 Authoring space

All scene geometry is authored in a 402 × 216 box (the prototype's phone width × header height). Paint it into the real rect with a single uniform scale on the width, and let the drawing bleed below the box — the backdrop runs the full height of the app, so the sky's bottom band stretches. Anchor the layered shapes to the top of the rect and stretch only the last gradient stop.

Path data uses absolute commands only — M L Q C Z, no arcs, no relative h/v. That is a hard constraint, not a preference: the scaler offsets every number as an absolute x,y pair, and a relative command would be scaled as if it were a point. A twenty-line parsePath covering those five commands is all you need; run it once at startup and cache the Path objects per scene.

2.3 Time-of-day wash

Over the scene, one full-bleed overlay tinted by the local clock: morning warms, afternoon is neutral, evening goes amber, night goes deep blue. It is a single drawRect with a low-alpha colour — cheap, and it must be recomputed on resume, not only on cold start. Keep the four tints in the same table as the palettes so a designer can retune them in one place.

2.4 Ambient drift

Each scene carries one drift effect: 18–26 small shapes on a single repeating AnimationController, each with a deterministic per-index phase offset and duration (hash the index and the scene key — no Random, so it looks the same across rebuilds). Snow and petals fall and rotate; rain falls fast with a slight lean; leaves tumble; dust and breeze cross horizontally; fireflies pulse in place.

Non-negotiable: honour MediaQuery.disableAnimationsOf(context) and the app's own Ambient motion setting by drawing zero particles — not by slowing them. Pause the controller when the app is backgrounded or the scene is off-screen; this is the only always-running animation in the app and it must not cost battery on the lock screen.

2.5 Glass, sill and parallax

The window treatment sits between the scene and the content: a faint diagonal sheen across the pane, a soft vignette at the edges, and a warm ledge where the glass meets the feed. Draw all three in the same painter, above the drift. The feed scrolls over it at full speed while the scene translates at one sixth of the scroll offset — drive that from the ScrollController offset inside a RepaintBoundary, and clamp it so the scene never lifts off the top of the screen.

3 · The avatar painter

An avatar is six small integers and nothing else — no upload, no crop, no CDN. It is drawn from ~40 primitives on the current village's sky, which is why a face from the Winter village and one from Tropical still look like the same hand drew them.

Avatar geometry is authored in a 78-unit square and painted at any size by uniform scale; the same primitives from §2.2 apply, with the same absolute-coordinates-only rule. Sizes in use: 26 px (feed row), 34 px (status row), 44 px (header / village switcher), 96 px (Me), 216 px (the avatar editor, drawn on the full village sky). Cache each spec+size as a ui.Picture — feed rows redraw constantly and there is no reason to re-run the paint list.

A user may add one companion — dog, cat or baby — with the same six integers plus a coat index. It belongs to the user, not the village, and appears on the routines they check for it.

4.1 Social rules the UI must enforce

  • Exactly four reactions — heart, thanks-hands, smile, star. No counters racing, no reaction picker, no sixth option later.
  • One daily status line per person; it expires, and it never sends a notification.
  • Push is actionable (thank-you and note from the notification itself) and rare.
  • One scheduled notification a week: the Sunday digest, written as a letter — the week in three numbers, two moments, and who has gone quiet.
  • Leaving a village takes your updates and photos with you; recipes are yours to keep or leave behind — the leave sheet must ask, not assume.

5 · Accessibility & text size

Half the village is over sixty. Large text is not a mode — it is the same screens at the system's scale factor, tested to 150%: layouts go vertical, reaction rows collapse behind a single button, and every hit target stays at least 56 px. Never cap textScaler, never put text in the painters, and give every drawn avatar a Semantics label with the person's name.

6 · Platform

Two things stay native: modal sheets and the invite share action. Everything else is drawn by the app and should be pixel-identical on iOS and Android — including the tab bar, which is a Tahan widget rather than a platform one, so the active-tab accent follows the scene.

7 · Open before build

  • Upcoming events — event details plus planning boards (who brings what, voting on activities). Designed next session; leave a tab-agnostic slot in the feed's card variants for it.
  • "Who sees me?" — one screen that answers the privacy question plainly, per village.
  • Moderation take-down view — what an admin sees when they remove a post, and what the author is told.
  • Sync & offline — not designed. The feed must open with content in a farmhouse kitchen with one bar; decide the local store before the first screen is coded.
